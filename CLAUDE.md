## Источник истины

- `DESIGN.md` — единственный источник дизайн-решений: цвета, типографическая шкала, отступы, радиусы, компоненты и их состояния, запреты, чеклист §12. Читай его перед любой задачей по UI.
- Приоритет при конфликте: `DESIGN.md` → этот файл → любой установленный скилл (frontend-design, gsap-skills, web-design-guidelines). Скиллы — техническая справка по библиотекам и доступности, не источник дизайн-решений.
- Брендбук — источник логотипов, фирменных форм (WIND, SUN, ROCK), паттернов и запретов на их модификацию. Логотип и формы только из SVG, никогда не перерисовывать и не перекрашивать за пределами палитры.

## Токены неприкосновенны

- Цвета только из §3.1 `DESIGN.md`, по hex. Никаких новых оттенков, opacity-вариантов брендовых цветов, Tailwind-серых, «почти белых».
- Шрифты только Unbounded и Mulish. Размеры только из таблицы §4.1. Если размер «не подходит» — это повод сообщить, не повод добавить новый.
- Токены (цвета, размеры, отступы, радиусы) меняет только человек через `DESIGN.md`. Ты можешь предложить изменение с аргументом, но не применять его сам.
- Исключения из правил (капс в хиро, двухцветный h2, скраб-видео, ротация цифр) перечислены в `DESIGN.md`. Новых исключений самостоятельно не вводить.

## Как работать

- Перед сдачей любого экрана или секции прогони чеклист §12 `DESIGN.md` и приложи список: что проверил, что исправил, что осталось. Без этого списка задача не считается выполненной.
- Текст на фото или видео: цвет выбирается замером контраста на реальных пикселях под блоком (95-й перцентиль яркости), норма 4.5:1 для текста и 3:1 для display. Решение проблемы контраста — позиция блока, кроп, цвет текста. Не скримы, не градиенты, не плашки, если они явно не разрешены в задаче.
- Альтернативные варианты — всегда новый компонент с суффиксом варианта. Существующие компоненты не перезаписывать и не удалять без прямого указания.
- Новые зависимости не добавлять без запроса.
- Если данных для компонента не хватает (копи, изображение, тайминги, партнёрские логотипы) — спроси или поставь явный плейсхолдер с пометкой `TODO:`. Контент не придумывать.
- Один id — один элемент. Id не выводятся из текста; при нескольких экземплярах компонента на странице используй уникальные id на экземпляр.

## Видео и медиа

- Видео для скраба по скроллу перекодируется с ключевым кадром на каждом кадре:
  `ffmpeg -i in.mp4 -an -c:v libx264 -g 1 -keyint_min 1 -pix_fmt yuv420p -crf 20 -movflags +faststart out.mp4`
  Две версии: 1080p и 720p (`<source media>`), в `public/video/`.
- Фон пиновой секции в покое — первый кадр её видео-отрезка, не отдельный рендер.
- Одни и те же кадры не используются в двух секциях.
- Скраб: прогресс считать в `requestAnimationFrame`, `currentTime` ставить при разнице > 1/30 с, `preload="metadata"` до приближения секции, затем `auto`. Feature-detect: если первые seek'и > 80 ms или `prefers-reduced-motion` — статический режим.
- Все изображения с `alt` на украинском. Декоративные формы и паттерны — `aria-hidden`.

## Адаптивы и доступность

- Каждая секция сдаётся на 1440, 1024 и 390. Мобайл не упрощается молча: если что-то не помещается — предложи решение и сообщи.
- `prefers-reduced-motion` — статический режим для всех анимаций. Все тексты всегда в DOM.
- Фокус видим на каждом интерактивном элементе (2 px `accent-deep`). Модалы запирают фокус и закрываются по Esc. Тач-цели не меньше 44 px.
- Лейблы связаны с полями через `for`/`id`, не через обёртку.

## Производительность

- Анимируем только `transform` и `opacity`. `will-change` ставить перед анимацией, снимать после.
- В DevTools Performance при скролле — без long tasks > 50 ms на 1440 и на эмуляции Moto G Power. Результат замера — в отчёт.
- Изображения — WebP/AVIF с `width`/`height`, ленивая загрузка ниже первого экрана.
